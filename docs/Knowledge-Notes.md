# 第一部分 · 行业术语（招标世界的黑话）

## 1.1 招标的基本角色与流程

**招标人**：出钱买东西的一方（比如水务集团要买装载机）。
**投标人**：想卖货的一方（我们的客户——经销商，代表某制造商去投标）。
**代理商 vs 制造商**：制造商=工厂；代理商=拿厂家授权帮厂家卖货的公司。我们资料库里的"浙东机械"就是代理商——所以投标时必须附**制造商授权书**，否则没有资格卖别人的货。
**招标公告 vs 招标文件**：公告是"征婚启事"（概述需求、时间、资格）；招标文件才是"完整合同草案"，其中最关键的是**第四章技术要求**（参数都在这里）。⚠️ 我们演示用的只是公告+参数摘要，真实投标要拿到完整文件逐条核对。
**开标**：所有投标人在同一时间当众拆封报价（本项目的电子标就是在线解密）。开标≠评标，评标是之后的专家打分。

## 1.2 那些一票否决的东西（废标机制）

**废标 / 否决投标**：不是扣分，是**直接出局**。常见触发条件：
- ★关键参数不满足（见下）
- 报价超过**最高限价**（招标人说"我最多出34.025万"，你报34.1万=出局）
- **保证金**没交对：金额错、晚到账、用了老板个人卡而不是公司**基本账户**、分两笔汇——都可能无效
- 电子标**解密超时**：开标后限时（如60分钟）用CA锁解密你的加密标书，解不开=视为放弃
- **授权书**没盖投标人公章、型号对不上

**★关键参数**：招标人在最重要的参数前打★（如"★标准斗容 ≥2.7m³"），意思是"这条不满足直接出局，其他条款你都可以谈，就这条不行"。→ 这就是为什么v1.4我们要做★识别和废标红条。

**正偏离 / 负偏离**：偏离表里对每条参数表态的术语。
- 招标要求"≥2.7m³"，你有3.0m³ → **正偏离**（比要求还好，加分项）
- 要求"≥2.7"，你只有2.0 → **负偏离**（不达标，危险）
- 刚好相等 → **满足**
- 注意细节：整机质量≤18t这种**上限型**要求，你17.5t只是"满足"不算正偏离——轻不一定是优点。→ 这就是引擎里"上限型达标即满足"规则的由来。

**资格后审**：开标后再审你的资格（不是投标前先审）。意味着所有证明材料必须**随标书一次交齐**，缺一项就完。

**联合体**：两家公司组队投标。本标"不接受联合体"→ 必须独立投。

**CA数字证书**：电子标世界的"电子身份证+签名章"，办一个要2-5个工作日——所以行动时间表里它排在最前面。

**澄清/补遗**：招标人中途发的"修改通知"（改参数、改时间）。漏看一份补遗是真实废标高发原因——v1.6的"公告变更检测"就是为它而生（见2.2⑥）。

# 第二部分 · 运行机制（产品内部是怎么工作的）

## 2.1 一张图看懂数据流

```
你粘贴的两段文本                规则引擎（engine.js，三步）           你看到的成果
┌─────────────┐   ┌──────────────────────────────┐   ┌──────────────┐
│ ①本公司资料库 │ → │ ①提取：从文本里"找"参数和关键信息 │ → │ 资格自查表     │
│ ②招标公告    │ → │ ②判定：换算单位、逐条比大小      │ → │ 技术偏离表     │
└─────────────┘   │ ③汇总：算评分、排风险、给结论     │ → │ 废标风险TOP5   │
                  └──────────────────────────────┘   │ 结论与评分     │
                                                     └──────────────┘
```

记住这句话就懂了产品本质：**"读文本→提数字→比大小→算总分"，全程是精确计算，不是AI在猜。**

## 2.2 五个核心机制（每个配一个类比）

**① 关键词匹配（正则表达式）——产品的"眼睛"**
类比：高级版Ctrl+F。不只找词，还找"模式"。
引擎里写着类似这样的规则："找到'额定载重'这个词，抓它后面跟着的数字和单位"。
所以"额定载重量 5000kg"能被读出来；如果公告写的是完全不认识的表述，引擎就老实说"未检索到，请人工核对"——**这不是缺陷，是诚实**。
（正则表达式=用符号描述文本模式的语言，比如"\d+kg"意思是"若干个数字后跟kg"。你不需要会写，知道它=精确找文本即可。）

**② 单位换算——先统一度量衡再比大小**
类比：一个说"我跑了3000米"，一个说"我跑了3公里"，先都换算成米才能比。
所以"3.1m"和"≥2900mm"能自动比对（2900mm=2.9m，3.1>2.9，正偏离）。
而"爬坡能力65%"和"要求30度"——百分比和角度是两套不同的度量衡，**没有固定换算公式**，引擎就拒绝比，标注"待人工核对"。→ 理念：宁可不判定，不可错判定。

**③ 上下限语义——同样是"达标"，含义不同**
- "斗容≥2.7m³"是**下限型**：越大越好。你有3.0 → 超出要求 → 标"正偏离"（可以吹的卖点）
- "整机质量≤18t"是**上限型**：不超就行。你17.5 → 只是"满足"（没人会因为你的车轻就加分）
→ 这是v1.1修的重要语义：正偏离只留给"越大越好"的参数，避免答辩时被评委抓住"轻=优？"的反例。

**④ ★段级定位——用分号把一句话切成参数段**
问题：一行写着"额定载重量≥5000kg；★标准斗容≥2.7m³；额定功率≥160kW"，如果只看整行有没有★，三个参数都会被误标。
解法：以分号（；）把行切成小段，★只属于它紧邻的那个参数段。
→ 类比：点名时按座位号点名，而不是全班起立。140项测试里专门锁定了这个行为。

**④补充 · 公告变更检测——像"改错对比"一样看两版公告**
场景：招标人发补遗，把限价从35.8万改成34.025万、开标提前两天、某参数加了★。人工肉眼对比两版长文，极易漏。
做法：系统分别从两版提取关键信息和参数，然后逐项"对答案"——不同的全部亮出来，高风险的排前面，每条给一句"怎么办"。
类比：老师把你和标准答案逐题对照，错的地方红笔圈出来，还写上批注。
→ 关键点：它不做任何"猜"，只做"提取+对照"，所以结论100%可靠。

**④补充 · ▲重要条款——和★是两套体系**

真实采购文件里除了★（不满足直接出局），还有▲（不满足影响评分、要扣分但不废标）。
产品v1.7把两套体系分开处理：★负偏离→红色废标警告；▲负偏离→琥珀色"复核提醒"。
答辩金句素材："★管生死，▲管名次——我们把两种红线的轻重分清楚了。"

**⑤ 评分模型——扣分制，不是加分制**
起点100分，做错题扣分：负偏离一项扣15（几乎判死刑）、缺参数扣6、待核对扣5、缺证明扣3。最后落在0-100，映射四档：
A≥85建议投标 / B 70-84补料后可投 / C 55-69谨慎 / D<55暂缓。
两个设计点（答辩常问）：
- 为什么负偏离扣最狠？因为它最接近废标。
- 为什么权重可调？不同行业在意的东西不同（权重=业务价值观），但脚注必须随报告输出，让人看到"这个分是怎么算的"——这叫**可解释性**。

## 2.3 反幻觉机制（为什么大模型不说胡话）

通用大模型（ChatGPT类）的本能是"接话"——你问参数，它特别乐意编一个像模像样的数字。投标场景里编一个参数=废标+法律责任。

我们的三层防线：
1. **输入层·白名单**：系统提示词规定"只允许引用资料库和公告两份输入"（提示词=给AI的岗位守则）。
2. **判定层·不经过AI**：所有数字比较由代码完成，AI碰不到。
3. **输出层·占位符协议**：缺信息必须原样输出"该信息不在本公司资料库中，请核实后补充"。

所以业务员看到"待核实"三个字，知道这是**待办事项**，不是错误——这是产品与"直接问ChatGPT"的分水岭。

### 2.3b 自定义词库——给引擎发一本"外号册"

引擎认识"标准斗容"，但资料库若写"额定容积"它就不认识了（老实标"资料库无"）。
v1.6的词库：你登记"额定容积 = 标准斗容"，以后引擎见到外号就知道是谁，判定照常进行。
两个讲究：
- **诚实标注**：偏离表会写明"资料库以「额定容积」表述，依自定义词库匹配"——来源可追溯，不含糊；
- **可删除**：登记错了随时删，词库存本机。
→ 这就是"规则库随使用生长"：每用一次产品，它对这家公司的表述就多认识一点。

## 2.4 双引擎的关系

- **规则引擎**（engine.js）：像**计算器**。快、准、离线、结果永远一样。承担所有判定。
- **大模型引擎**：像**作家**。语言流畅、能聊天，但可能出错，必须人工复核。
- 计算器保底，作家加分——这就是答辩里"双引擎架构"的完整说法。

## 2.5 五个技术名词的最小理解（够答辩用）

| 名词 | 一句话理解 | 在产品里 |
|---|---|---|
| 前端/后端 | 前端=你看得见的界面，后端=幕后干活的程序 | index.html是前端，engine.js是后端 |
| 纯函数 | 同样输入永远得到同样输出的"老实函数"，像计算器 | engine.js整个是纯函数，所以能离线、能测试 |
| localStorage | 浏览器自带的小仓库，存你本机的小数据 | 历史、设备库、API密钥都存这里，不上传 |
| 自动化测试 | 写一段程序自动"对答案"，改坏任何一处立刻报警 | tests/engine.test.js，133道题全对才放行 |
| PWA | 给网页发"App身份证"，让它能装到桌面/手机 | manifest.json+sw.js，安装后断网可用 |

# 第三部分 · 学习路径与自测

## 3.1 三个实验（30分钟，动手体会机制）

**实验1 · 体会"不编造"**：打开产品→清空资料库→随便粘一段新闻→生成分析。
预期：所有参数都标"资料库无/待人工核对"，零编造。→ 这就是反幻觉。

**实验2 · 体会"单位换算"**：在资料库里把"标准斗容 3.0m³"改成"标准斗容 2800L"（升）…（引擎暂不认升，会标待核对——记住这个边界感）再把挖掘机场景公告里"≥6500mm"改成"≥6.5m"，观察结论不变。→ 理解"能换算的自动换，不能换算的不瞎换"。

**实验3 · 体会"★废标"**：切到挖掘机场景，把资料库里"爬坡能力 65%"改成"爬坡能力 75%"→重新分析。
预期：废标红条消失、评分回升。→ ★参数满足与否，一票定生死。

**实验4 · 体会"公告对比"**：切到"🔀 公告对比"标签 → 点【载入对比演示】→【对比两版公告】。
预期：6条高风险变更（限价降了、开标提前、斗容要求提高并升★…），每条带"怎么办"。→ 澄清/补遗再也不怕漏看。

**实验5 · 体会"词库生长"**：点顶部【📖词库】→ 选"标准斗容"、输入"额定容积"、添加 → 把资料库里"标准斗容 3.0m³"改成"额定容积 3.0m³"→ 重新分析。
预期：偏离表照常判定正偏离，且多一行"依自定义词库匹配"的诚实标注。

## 3.3 一句话总结（背下来）

> **"标书快反"的本质，是把老师傅脑子里的投标避坑经验，变成一套可测试、可回溯、可生长的确定性规则；大模型只在我们划好的白名单里说话，缺的 info 一律说"请核实"，绝不编造。**
