## 一、战略定位

### 1.1 一句话定义
「出海通 TradePilot」是面向中国工程机械出口厂商与经销商的**多语言客户交互AI智能体**：用10秒专业应答海外询盘、自动生成PI形式发票草稿、准确解释外贸条款——并继承标书快反的反幻觉铁律：**知识库里没有的信息，绝不编造。**

### 1.2 为什么是正统续作（三条战略依据）
1. **赛道补全**：AI+运营赛道要求"需求分析、文件生成、客户交互"三类智能体。标书快反（需求分析+文件生成）已占两席，出海通补齐第三席——团队成为赛道内少数"三类全做"的队伍。
2. **知识库复用**：海外买家询盘的核心问题（斗容、功率、爬坡能力、起升高度）与国内投标完全同源。标书快反积累的32类参数知识库，换一种语言问法即是外贸话术库——**知识库是一个，市场是两个**。
3. **专业绑定**：Incoterms、国际结算、报关报检是国际贸易专业的课程内核。团队成员的专业学习直接构成产品的需求文档与规则来源，形成"课堂即研发"的独特开发模式。

### 1.3 市场背景
中国工程机械出口持续增长，头部厂商（三一、徐工、临工等）海外收入占比快速提升，带动大量中小出口商与经销商跟进。中小出口商普遍缺乏专业外贸团队：询盘回复慢、英文报价不专业、条款风险意识弱。通用AI工具（如平台自带助手）不懂得工程机械参数与出口合规，垂直深度是空白。

## 二、目标用户与核心场景

### 2.1 目标用户
- 中小型工程机械出口商的外贸业务员（主力用户）
- 有闲置外贸产能的国内经销商（复用标书快反同一客户群）
- 工厂海外销售部（定制版潜在客户）

### 2.2 核心场景：跟着外贸业务员的一天
| 环节 | 业务员现状 | 出海通做什么 |
|---|---|---|
| 海外询盘进来（阿里国际站/邮件/WhatsApp） | 半天到一天才回复，语言不专业 | 多语言专业应答**草稿**10秒生成，参数从知识库引用，业务员审核后发送 |
| 买家追问技术细节 | 来回翻样本手册 | 32类参数精确应答："铰接转向角"这类问题绝不瞎编 |
| 报价阶段 | PI手写模板，字段常漏 | **PI草稿自动生成**+11项字段完整性检查 |
| 条款纠结 | FOB/CIF分不清，怕被坑 | Incoterms义务矩阵问答+风险提示 |
| 买家改单 | 手动肉眼对比 | PI/CI新旧版本自动比对（复用公告变更检测） |
| 判断优先级 | 凭感觉跟进 | 询盘成熟度评分，帮你先跟最可能成交的 |

## 三、总体架构（双引擎迁移）

### 3.1 架构图
```
海外买家询盘（EN/ES/RU/AR）
        ↓
┌─────────────────────────────────────┐
│ 贸易规则引擎（确定性 · 可测试）          │
│  · 参数查询：32类知识库直查             │
│  · Incoterms 2020 义务矩阵             │
│  · PI 11项字段完整性校验                │
│  · 付款条款一致性检查（定金+尾款）        │
│  · 询盘成熟度评分                       │
└─────────────────────────────────────┘
        ↓ 结构化结果（数字与条款100%来自规则引擎）
┌─────────────────────────────────────┐
│ 大模型引擎（语言层 · 白名单约束）         │
│  · 多语言商务信函润色                   │
│  · 开放式追问应答                       │
│  · 反幻觉协议：缺失信息输出占位符         │
└─────────────────────────────────────┘
        ↓ 草稿
   业务员人工审核 → 发送
```

### 3.2 反幻觉铁律的跨语言迁移（核心设计）
国内场景：编造参数=废标；外贸场景：**编造参数=合同纠纷+退货索赔+法律责任**，赌注更大。
- **规格数字语言无关**：从知识库查出的数值嵌入多语言模板，大模型只负责包装不负责事实；
- **条款代码国际化**：Incoterms三字码（FOB/CIF/DAP…）是全球统一语言，规则引擎按代码查义务矩阵；
- **占位符协议延续**：缺失信息一律输出"to be confirmed"，业务员拿到的是补料清单而非错误答案。

## 四、核心功能模块（四大件）

### 4.1 模块一：多语言询盘应答智能体（MVP核心）
- 输入：买家原始询盘（任意语言）+ 卖家选择的产品；
- 输出：商务信函草稿（称呼/致谢/逐条回答/附件清单/签名栏），技术参数全部来自知识库并标注出处；
- 确定性规则：产品存在性校验（知识库无此型号→占位符）、规格数值直查；
- 语言路线：英文先行（MVP），西/俄/阿二期。

### 4.2 模块二：PI形式发票生成智能体
- PI十一项必填字段：买卖双方信息、品名与规格、数量、单价、总金额、**贸易术语+港口**、付款方式、交货期、有效期、原产地、签章栏；
- **字段完整性检查**（对标就绪度评分逻辑）：缺失/矛盾逐项提示；
- **付款条款一致性规则**：如"T/T 30%定金+70%见提单副本"——尾款条件与交货方式矛盾时报警；
- 版本变更：买家要求改量/改港/改条款时，新旧PI自动diff并按风险分级（复用公告变更检测引擎）。

### 4.3 模块三：贸易条款问答智能体
- **Incoterms 2020义务矩阵**：11种条款×（运输/保险/出口清关/进口清关/风险转移点）的确定性义务表，问答时按矩阵回答而非模型自由发挥；
- **国际结算常识**：T/T、L/C即期、D/P的流程与风险提示；
- **出口认证导向**：提及欧盟市场→提示CE机械指令；俄语区→EAC；美国→EPA排放；尼日利亚→SONCAP（矩阵化知识，持续扩充）；
- 合规兜底：所有条款回答附"仅供参考，具体以合同与目的国法规为准"。

### 4.4 模块四：询盘成熟度评分（lead scoring）
- 0-100分评估询盘质量：信息完整度、专业度（是否问具体参数）、采购紧迫性（有无工期）、公司实体线索；
- 输出"优先跟进/正常跟进/谨慎判断"三档建议——**把标书快反的评分方法论平移到销售线索管理**，形成方法论品牌一致性。

## 六、语言与本地化策略

1. **MVP仅英文**：商务英文是行业标准语，规则验证成本最低；
2. **二期西/俄/阿**：大模型翻译能力足够，但话术模板（称谓、敬语、节奏）需逐语言打磨并请母语者校订；
3. **文化红线**：坚持"AI起草+人工发送"——智能体永远不当签名人；宗教节日节奏、称谓习惯等以人工判断为准；
4. **语言与反幻觉解耦**：事实层（数字/条款）语言无关，语言层只做包装——这是跨语言不失控的架构保证。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 阿里国际站等平台自带AI助手 | 差异化在垂直深度：平台助手不懂机械参数与出口合规矩阵；我们"懂参数、懂条款、懂认证" |
| 多语言商务文化细节出错 | AI起草+人工发送铁律；逐语言母语校订后再上线 |
| 条款解释引发责任争议 | 全部条款回答附免责声明；义务矩阵仅作科普不构成法律意见 |
| 知识库建设周期 | Incoterms矩阵与HS编码为成熟公开知识，团队专业课程内容直接转化；认证矩阵逐市场滚动建设 |
| 与标书快反资源冲突 | 共用架构与部署管线，知识库独立；两产品面向同一客户群，销售可交叉导流 |

## 九、成功指标（MVP验收线）

1. 询盘应答草稿的业务采纳率 ≥ 60%（试点业务员人工评定）；
2. PI字段完整率 100%（11项校验全过才允许导出）；
3. 条款问答与Incoterms矩阵比对准确率 100%（确定性规则，可全量测试）；
4. 规则引擎新增断言 ≥ 30项（贸易规则测试集），全部通过；
5. 3家出口商完成免费试点并出具使用反馈。

## 十、合规与数据声明

- 条款解释仅为知识科普，不构成法律或贸易实务意见；
- 试点询盘数据须脱敏后入库，尊重买家隐私；
- 产品不代替外贸单证员签署任何具有法律效力的文件；
- 内置演示数据均为虚构。
